# Mandarin Lens — screenshot + source review (29 October 2026)

Scope: uploaded v1.3 screenshots/review notes, and the actual connected repository source. This is an implementation review, not an independent security certification. The screenshots show a local Chrome video fixture, not a broad compatibility test.

## Implemented on the review branch

1. Refine browser word segmentation using the curated glossary. Unknown Han-only browser tokens such as `我想` split into separately clickable `我` and `想`, while known words like `咖啡` remain whole.
2. Put Chinese punctuation on the Hanzi row by attaching punctuation to the preceding word's character label, rather than after pinyin.
3. Replace the word popover's ambiguous ellipsis with **Context**, increase action hit areas to 32 CSS pixels, and allow a modestly wider popover.
4. Replace the wide preparation toolbar with a narrow two-column layout and full-width status line. Preserve the existing control flow and permissions.
5. Add deterministic segmentation coverage and integration assertions for tokens, punctuation and expanded popover bounds.

## Still missing — recommended implementation order

**P0: Captions vs audio.** This version does NOT transcribe video audio. It can translate accessible captions and imported subtitle files, not arbitrary videos without captions. Keep this limitation clear. Any future optional offline speech recognition must be opt-in, locally processed, measured for resource use and permissions, and never silently capture tab audio.

**P1: Better learning mode.** Add a discoverable click-only definition mode; hold-to-reveal English and pronunciation; configurable tone-coloured pinyin; sentence-level context that explains grammar such as `想` vs `要` without inventing certainty.

**P1: Import and preparation.** Support paired Chinese/English timestamped imports so existing translations are reused and pinyin generated locally. Show real cache completeness, preparation model status, model download/unsupported device, and unambiguous cancellation/resume status.

**P1: Targeted practice.** Add a 2×/3× repeat at 0.75× speed with automatic return to original playback speed; per-video saved vocabulary with time-linked example, pronunciation replay and local spaced review; avoid surprising pausing and unexpected speech.

**P1: Video UI.** Keep subtitles minimal while watching; reveal keyboard-accessible controls deliberately. Persist word explanation mode and make menu/subtitle focus order predictable; respect reduced motion, text scaling, high contrast and fullscreen safe areas.

**P2: Quality and device coverage.** Validate long/rapid cues, multiline dialogue, punctuation across quotes, non-BMP Han, simplified/traditional differences, polyphonic readings, different subtitle providers, SPA navigation, multiple players, native fullscreen and PiP behavior. Add performance snapshots during 60–120 minute sessions. Improve dictionary coverage with an appropriately licensed source and clearly label model-produced definitions.

## Release acceptance checklist

- Run `npm test`, `npm run check`, `npm run build` and real packaged Chromium browser tests. Existing tests can use mock translation; do not present those as linguistic-quality proof.
- Re-run real Chrome on-device model tests for both directions. Keep actual-model evidence distinct from mocks.
- Test several real permitted videos with high-contrast, low-contrast, busy backgrounds and rapid subtitles at 100%, 125% and 150% scaling, plus keyboard-only and screen reader use.
- Confirm only documented `activeTab`, `scripting`, `storage` permissions; inspect CSP, inert text handling and local-data deletion; no unauthorized network or capture.
- Update release version, README, screenshots and changelog only after passing validation. Do not overwrite the public v1.3 package with unverified source.
